# منصة المحكمة الرقمية

منصة للمسار الرقمي الكامل للقضية المدنية والتجارية في ضوء القانون رقم 58.25 المتعلق بقانون المسطرة المدنية. تبنى على مراحل من 0 إلى 9. وأنجز في هذا المستودع إلى الآن: **المرحلة 0، التأسيس والأمان والنشر الأول**.

المنصة في طور البناء. وتشتغل نسخة العرض بمعطيات خيالية كلها، ولا يدخل إليها معطى حقيقي.

## ما تحتويه المرحلة 0

- النواة (`packages/core`): الصفات الست والعشرون، وجدول الإجراءات، ودالة الصلاحيات الوحيدة، وفهرس أحداث السجل، وسلسلة التجزئة، وفحص الإقلاع، وثوابت سياسة الأمان. وهي TypeScript خالص لا يعرف الويب ولا قاعدة المعطيات.
- التطبيق (`apps/web`): Next.js 16 مع طبقة واجهات برمجية تعرف كل مساراتها بـ`defineEndpoint`، وطبقة خدمات في `src/server`، والـworker في `src/worker`، وأدوات العرض في `src/demo`، وهي وحدة معزولة.
- الدخول: كلمة المرور، ثم وسيلة التأكيد الثانية، ثم اختيار الصفة إن تعددت الصفات. ومعها القفل المؤقت بعد المحاولات الخاطئة، وإعادة التحقق من الهوية قبل الأفعال الحساسة، وجلسة عمل محدودة المدة.
- سجل أحداث لا يعدل ولا يمحى: ترفض قاعدة المعطيات تعديله وحذفه، وكل سطر مسلسل بتجزئة مفتاحية، ويتحقق الـworker من السلسلة دوريا.
- لوحة البداية بخاناتها الثلاث، والإشعارات، والحساب الشخصي، وإنشاء الحسابات من قبل مدبر النظام.
- الصفحات العامة: صفحة الاستقبال، وتتبع الملف، وجدول الجلسات.
- أدوات بيئة العرض: تبديل الحساب، وصندوق الرسائل الصادرة.

خطة المرحلة في `docs/phases/phase-0.md`، وعقدها الهندسي في `docs/phases/phase-0-contract.md`، ومذكرتها الأمنية في `docs/security/phase-0-memo.md`.

## التشغيل محليا

المتطلبات: Node.js 22، وPostgreSQL 18 (ويكفي 16 فما فوق محليا).

1. تثبيت الحزم من جذر المستودع:

   ```
   npm ci
   ```

2. إنشاء دور المالك وقواعد المعطيات الثلاث (`mahkama_dev` و`mahkama_test` و`mahkama_e2e`)، مرة واحدة، بصلاحيات المستعمل الأعلى لـPostgreSQL. وتقرأ كلمة المرور من متغير البيئة ولا تكتب في أي ملف:

   ```
   sudo -u postgres env OWNER_PASSWORD='…' bash scripts/local-db-setup.sh
   ```

3. نسخ `.env.example` إلى `apps/web/.env` وملء قيمه. الملف غير متتبع في git. وتولد الأسرار هكذا:

   ```
   openssl rand -base64 48   # SESSION_SECRET
   openssl rand -base64 32   # SECRETS_MASTER_KEY
   openssl rand -hex 16      # ACCESS_CODE (كلمة عبور الزوار، عشرون حرفا فأكثر)
   ```

4. الهجرات، ثم تهيئة دور التشغيل، ثم بيانات العرض:

   ```
   npm run db:migrate
   npm run db:roles
   npm run db:seed
   ```

5. التطبيق والـworker، كل منهما في نافذة:

   ```
   npm run dev
   npm run worker
   ```

ثم يفتح `http://localhost:3000`، وتدخل كلمة عبور الزوار (قيمة `ACCESS_CODE`).

### دورا قاعدة المعطيات

يتصل التطبيق بقاعدة المعطيات بدورين:

- **دور المالك** (`mahkama`، عبر `MIGRATION_DATABASE_URL`): يملك الجداول، ولا يستعمل إلا في الهجرات وتهيئة الأدوار وبيانات العرض.
- **دور التشغيل** (`mahkama_app`، عبر `DATABASE_URL`): لا يملك شيئا. ولا يملك على جدول الأحداث إلا القراءة والإضافة.

ينشئ `npm run db:roles` دور التشغيل بكلمة المرور `APP_DB_PASSWORD`، ويمنحه صلاحياته، ثم يتحقق منها. وفي وضع الإنتاج يختم قاعدة فارغة غير مختومة بختم «production». ويرفض التطبيق الإقلاع إذا كان دور التشغيل مستعملا أعلى، أو مالكا لجدول الأحداث، أو قادرا على تعديله.

## الوضعان: العرض والإنتاج

الكود واحد، ويحدد الوضع بالمتغير `APP_MODE`.

| المتغير | العرض | الإنتاج |
| --- | --- | --- |
| `APP_MODE` | `demo` | `production` |
| `DEMO_TOOLS` | `true` (تبديل الحساب وصندوق الرسائل الصادرة) | `false` إلزاما |
| `DEMO_BUILD` (وقت البناء) | `true`: تبنى مسارات العرض | `false`: لا تبنى مسارات العرض أصلا |
| `ACCESS_CODE` | كلمة عبور الزوار، إلزامية | غير مستعملة |
| `APP_URL` | `https://…` (و`http://localhost` محليا) | `https://…` إلزاما |

يظهر في بيئة العرض مؤشر هادئ «بيئة العرض». ويرفض وضع الإنتاج الإقلاع إذا وجد أيا مما يلي: مكون محاكى، أو أدوات العرض مفعلة، أو مسارات العرض مبنية، أو كلمة مرور بيانات العرض محددة، أو بيانات عرض في القاعدة، أو قاعدة غير مختومة بختم «production»، أو ساعة منصة مزاحة، أو عنوان غير مؤمن. ويمكن التحقق من ذلك دون تشغيل التطبيق:

```
npm run boot:check
```

ولا تهيأ بيانات العرض إلا في قاعدة مختومة بختم «demo» أو فارغة تماما. وإعادة تهيئتها تطلب اسم القاعدة صراحة:

```
cd apps/web && node --env-file=.env dist-server/seed.mjs --reset --confirm=mahkama_dev
```

## حسابات العرض

ثلاثون حسابا خياليا بأسماء من حروف الهجاء، في محكمتين نموذجيتين: «المحكمة الابتدائية التجارية النموذجية» و«محكمة الاستئناف التجارية النموذجية». ولا يمثل أي منها شخصا حقيقيا.

- كلمة المرور لجميع الحسابات هي قيمة `SEED_DEMO_PASSWORD`. يحددها مالك البيئة، ولا توجد في المستودع.
- رمز وسيلة التأكيد الثانية يقرأ في «صندوق الرسائل الصادرة» (`/demo/outbox`)، إذ لا ترسل في بيئة العرض رسالة حقيقية.

## الاختبارات

```
npm run check            # lint، والأنواع، واختبارات النواة والوحدات، وفحوص البنية
npm run test:int         # اختبارات التكامل على قاعدة mahkama_test
npm run test:e2e         # اختبارات المسار بـPlaywright على قاعدة mahkama_e2e (حاسوب وهاتف)
npm run events:verify    # التحقق من سلسلة سجل الأحداث
```

تقرأ اختبارات التكامل إعداداتها من `apps/web/.env.test`، واختبارات المسار من `apps/web/.env.e2e`. وكلاهما غير متتبع. ولا تعمل الأولى إلا على قاعدة ينتهي اسمها بـ`_test`، ولا الثانية إلا على قاعدة ينتهي اسمها بـ`_e2e`. ولتشغيل اختبارات المسار على النسخة المنشورة يحدد `E2E_BASE_URL`.

وتشغل CI عند كل دفع: lint والأنواع، واختبارات النواة والوحدات والبنية، وبناءين (بمسارات العرض ودونها) مع فحص لائحة المسارات، واختبارات التكامل على PostgreSQL 18، واختبارات المسار، وبناء صورة الحاوية مع فحص `/healthz`، و`npm audit`، وSemgrep، وgitleaks على التاريخ كله.

## النشر على Railway

التطبيق مصمم للنشر على Railway: خدمة `web` وخدمة `worker` من الصورة نفسها (`Dockerfile`)، وقاعدة PostgreSQL، ومستودع وثائق. والبنية موصوفة كودا في `.railway/railway.ts`. وخطوات النشر الأول التي يقوم بها مالك المشروع مفصلة في `.railway/README.md`.

ولا يدفع إلى `main` إلا بإذن صريح من المالك، ولا ينشر إلا بعد نجاح CI.

## قواعد لا تخرق

- الأصل المنع: كل مسار يتحقق في الخادم من الصفة ومن العلاقة بالمورد عبر دالة النواة الوحيدة.
- لا يقرأ الكود ساعة النظام مباشرة: الزمن يمر عبر `apps/web/src/server/clock.ts`.
- كل عملية تدون في سجل الأحداث، والسجل لا يعدل ولا يمحى.
- القواعد القانونية معطيات مؤرخة ومسندة، لا كود.
- لا سر في المستودع، ولا بيانات حقيقية في بيئة العرض، ولا شعار رسمي: موضع الشعار إطار محايد يملؤه الإعداد.
