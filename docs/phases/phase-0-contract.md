# Phase 0 — engineering contract (v2)

Binding technical contract for Phase 0 (`المرحلة 0: التأسيس والأمان والنشر الأول`).
Human plan: `docs/phases/phase-0.md`. Threat memo: `docs/security/phase-0-memo.md`.
The founding prompt `docs/build-prompt.md` wins over this file; the law text `docs/law-58-25.md`
(being produced from the Official Gazette PDF in `docs/sources/`) wins over both.

v2 integrates the independent design review of 24 Nov 2026 (security, prompt compliance, toolchain
feasibility). Every experimentally verified tool fact below comes from that review.

Code, identifiers and comments are English. Every string a user reads is Arabic (or the partial
fr/zgh translations) and lives in `apps/web/src/i18n/messages/**` — never in code.

When something here proves impossible, choose the simplest working alternative and record it in
`docs/decisions.md` (Arabic, one entry each: القرار، السبب، البديل المتروك، الأثر). Never weaken a
security control to make a test pass: stop and report instead.

Architecture rules — each enforced by an ESLint rule **and** an architecture test in `apps/web/tests/architecture/` (and `packages/core/test/architecture.test.ts`):

1. `packages/core` imports only `node:crypto` and `zod`. Nothing from `next`, `react`, `@prisma/*`, `pg`, `apps/`.
2. Only `src/server/**`, `src/worker/**`, `src/cli/**` may import `@/generated/prisma/**`, `@prisma/*`, `pg`. `src/proxy.ts` never touches the database.
3. Nothing outside `src/demo/**` imports `src/demo/**`, except the demo entry points of §9, and only through `import()`.
4. Reading system time (`new Date()` with no argument, `Date.now()`, `performance.now()`, `process.hrtime`) only in `src/server/clock.ts` and tests. `clock.systemNow()` may be called only from an allow-list: `src/server/auth/**`, `src/server/security/**`, `src/server/jobs/queue.ts`, `src/server/log.ts`. Every legal or displayed timestamp (events, notifications, outbound messages, future time limits) uses `clock.now()`.
5. No Arabic-script literal in `*.ts`/`*.tsx` outside `src/i18n/messages/**`, `src/cli/seed-data/**`, test files. Core stores legal bases as data (`{ law: '58.25', articles: [628] }`) and month names come from `Intl` (`ar-MA`, pinned by a unit test).
6. Every `src/app/**/route.ts` export is a `defineEndpoint` product registered in `http/registry.ts`; the registry has no entry without a file.
7. Every `page.tsx` and every `layout.tsx` under `(gate)` and `(app)` calls exactly one page guard (`requireGate`, `requirePending`, `requirePage`, `requireDemo`) as its first statement, and is listed in `http/page-registry.ts`.
8. No `'use server'` directive anywhere. No `$queryRawUnsafe` / `$executeRawUnsafe`. No string-built SQL.
9. `fetch`, `node:http(s)`, `node:net`, `undici` are banned in `src/server/**` except `src/server/outbound/` (empty in Phase 0: it will hold the closed list of provider hosts).
10. No inline `<script>` and no `style=` attribute in our JSX; no `dangerouslySetInnerHTML`.
11. Nothing in `src/server/**` reads `process.env` or opens a connection at module top level (lazy `getEnv()` and `getDb()`), so `prisma generate` and `next build` run with an empty environment (CI proves it).

### 4.3 events.ts and event-chain.ts

Closed event catalogue: `EVENT_TYPES: Record<EventAction, { outcome: 'DONE'|'DENIED'|'FAILED'; details: ZodObject }>`.
Details hold only ids, enums, counts, safe integers, hashes and booleans — **no free text, no e-mail, no name, no phone, no code, no token**. `appendEvent` validates against the schema and rejects unknown keys.

Catalogue (Phase 0): `access.code.accepted`, `access.code.rejected`, `access.code.blocked`, `access.denied` (reason, endpoint or page id), `access.throttled` (suppressedCount, windowStart), `auth.login.succeeded`, `auth.login.failed` (identifierHash, reason), `auth.login.blocked` (identifierHash), `auth.second-factor.issued`, `auth.second-factor.failed`, `auth.second-factor.succeeded`, `auth.second-factor.refused` (issuance cap), `auth.account.locked` (cause, until), `auth.role.selected`, `auth.logout`, `auth.session.expired` (idle|absolute), `auth.session.revoked` (cause), `auth.reauth.succeeded`, `auth.reauth.failed`, `account.activated`, `account.activation.failed`, `admin.account.created` (newUserId, role, courtId, requestReferenceHash, legalBasis), `admin.account.activation-reissued`, `notification.read`, `demo.account.switched` (fromUserId, toUserId), `demo.outbox.viewed`, `demo.data.seeded`, `demo.data.reset` (previousHeadSeq, previousHeadHash), `events.chain.verified` (headSeq), `events.chain.broken` (brokenAtSeq, reason), `system.boot` (mode, componentsSimulated).

### 4.5 security-policy.ts (thresholds; technical values recorded in decisions)

| Control | Rule |
| --- | --- |
| Password failures | keyed on `identifierHash` = HMAC(`identifier` key, normalised e-mail), whether or not the account exists. 5 failures in 15 min ⇒ lock 15 min. A success clears the count. Attempts during a lock are not counted and do not extend it |
| Device cookie | after a completed second factor, `__Host-mr-device` (signed, 180 days, per account). Attempts carrying a valid device cookie for that identifier are counted in their own bucket, so an attacker can lock unknown browsers but not the owner's usual one (OWASP device-cookie scheme) |
| Second factor | 6 digits from `crypto.randomInt`, stored as HMAC (`second-factor` key), valid 5 min, constant-time compare, atomic consumption. Wrong codes counted **per account** over 15 min across all challenges and sessions: the 5th ⇒ every open challenge voided, every pending session of the account revoked, account locked 15 min. Reset only by a successful second factor. Issuance (login + resend) capped per account: 5 / 15 min, 20 / day — beyond, same 423 and no message. One pending session and one open challenge per account (a new login revokes the older one). Pending session lifetime 10 min |
| Signature PIN (Phase 1) | same shape, 3 failures ⇒ 15 min |
| Access code | per client: 10 failures / 15 min ⇒ blocked 15 min; global (any client): 50 failures / 15 min ⇒ new attempts refused 15 min (holders of a valid access cookie unaffected) |
| Login per client | 20 attempts / 15 min per client id, 429 |
| Activation | 10 attempts / 15 min per client |
| Case lookup | 10 / 5 min per client; global 300 / 5 min |
| Hearings list | 30 / 5 min per client; dates within today −7 … +60 days |
| Unauthenticated refusals | logged individually up to 30 / min per client; beyond, 429 and one `access.throttled` event per client and minute carrying `suppressedCount` |
| Authenticated refusals | 60 / min per session, then 429 and one aggregated event |
| Demo endpoints | 60 / min per client |
| Body size | 16 KB max before parsing; every zod string has a `max` (password 128, e-mail 254, code exactly 6 digits, names 120) |
| Argon2 | semaphore of 4 concurrent hashes; runs only after throttle and lock checks |

## 5. apps/web/src/server

All modules `import 'server-only'` (aliased to a shim for Vitest and esbuild).

- `config/env.ts` (lazy), `keys.ts` (HKDF-SHA256 per purpose, cached).
- `log.ts` — JSON lines; logs path without query string, status, duration, correlation id, ids. Errors logged as class + code + correlation id, never `message`/`detail` of database errors. A redaction test proves known secrets, codes, tokens, passwords and seeded e-mails never reach output.
- `db.ts` — lazy Prisma singleton on `globalThis`, pg adapter, connection with `statement_timeout` 15 s and `lock_timeout` 5 s.
- `clock.ts` — the only reader of system time. `now()` = system time + `PlatformClock.offsetSeconds` (read with short caching; ignored and asserted 0 in production). `systemNow()` per §2 rule 4. Advancing the clock lives only in `src/demo` (Phase 1+).
- `events/append.ts` — `appendEvent(tx, input)`: must be the **last statement before COMMIT** of a READ COMMITTED transaction; takes `pg_advisory_xact_lock` with `tx.$executeRaw` (never `$queryRaw`), reads the head, inserts `seq + 1` with the keyed hash. No hashing, network or file I/O after it in the same transaction. `appendStandaloneEvent(input)` opens its own transaction — used for DENIED/FAILED events, always after the business transaction ended, so a rollback never erases a refusal. If the DONE event cannot be written, the action rolls back. `seq` crosses the service boundary as `number` (no bigint leaves `src/server`). Concurrency test: 50 parallel appends ⇒ gap-free verified chain.
- `events/verify.ts` — incremental from the last anchor (`SystemState.chainHeadSeq/Hash`), full pass once a day; on failure `SystemState.chainStatus = 'BROKEN'` (shown to `SYSTEM_ADMIN` on the dashboard and on «مكونات بيئة العرض»), repeated at error level every run until cleared by a logged action. Each successful run writes the head to the technical log (an anchor outside the database).
- `auth/` — `passwords.ts`, `sessions.ts`, `login.ts`, `second-factor.ts`, `lockout.ts`, `device-cookie.ts`, `access-gate.ts`, `csrf.ts`, `reauth.ts`, `activation.ts`, `client-id.ts`.
  - `client-id.ts`: client address from **`X-Real-IP` only** (set by Railway's edge); `X-Forwarded-For` and `Forwarded` are ignored; IPv6 truncated to /64; missing/malformed header outside local development ⇒ one shared bucket `unknown` (strictest), never unlimited. Stored only as HMAC (`client-id` key). The closing review tests a forged `X-Real-IP` on the deployed instance.
  - Sessions: opaque 32-byte token, DB stores SHA-256; states `PENDING_SECOND_FACTOR`, `PENDING_ROLE`, `ACTIVE`; `origin` `LOGIN` | `DEMO_SWITCH`; `previousLoginAt` copied from `User.lastLoginAt` before update; absolute lifetime 12 h; idle per env; pending 10 min; cookie without `Expires`/`Max-Age`; requests with header `X-Background-Refresh: 1` do not update `lastSeenAt`; `reauthAt` set only by `/auth/reauth` (null after login, role selection, demo switch); token rotated at second factor, at role selection, at demo switch. A lock caused by re-authentication failures revokes that session; other locks never revoke ACTIVE sessions.
  - Guard re-reads `User.disabledAt` and `RoleAssignment.revokedAt` on every request; either ⇒ session revoked, `auth.session.revoked`, treated as no session.
  - Activation: 32 random bytes base64url, stored SHA-256, 24 h, link `${APP_URL}/activate#token=…` (fragment: read by the page script and POSTed, never in a URL the server sees); token validated first; unknown / used / expired ⇒ one `INVALID_TOKEN` answer; consumption `UPDATE … WHERE usedAt IS NULL AND expiresAt > now RETURNING`; password policy: 12–128 chars, not containing the e-mail local part; no session created; a new token voids older ones.
  - CSRF: `mr-csrf` is server-issued (random id + MAC; rejected if the MAC fails). Token = HMAC(`csrf` key, bindingId) where bindingId is the session id or the `mr-csrf` id. Access cookie MAC input includes SHA-256 of the current `ACCESS_CODE` (rotation revokes cookies). All comparisons `timingSafeEqual` on equal-length digests.
- `permissions/guard.ts` — builds the core `Subject` from the session; `requireGate()`, `requirePending(state)`, `requirePage(action, resource?)`, `requireDemo(action)` for server components; every refusal written with `appendStandaloneEvent` (subject to the refusal throttle).

- `messaging/` — `MessagingProvider` interface (`send({ channel, recipientUserId, templateKey, params, visibleToSessionId? })`), `simulated-outbox.ts` (the only writer of `OutboundMessage`, renders the body), `contract.ts` (reusable contract suite).

## 6. HTTP contract

Route handlers are `(req: Request) => Promise<Response>` reading cookies from `req.headers` (callable directly from Vitest).

```ts
defineEndpoint({ id, method, path,
  access: { kind: 'public' }                     // /healthz only
        | { kind: 'pre-gate' }                   // /api/v1/access only
        | { kind: 'gate' }
        | { kind: 'pending-session', states: [...] }
        | { kind: 'action', action }
        | { kind: 'demo', action },
  recentAuthMinutes?, params?: zod, body?: zod, rateLimit?, handler })
```

Order of checks, each failing closed and each refusal logged (`access.denied` with the step's reason, through the refusal throttle):

1. Body size and method.
2. Access gate (`mr-access`) unless `public`/`pre-gate` ⇒ 401 `ACCESS_CODE_REQUIRED`.
3. Mode for `demo` endpoints ⇒ 404 `NOT_FOUND` (same body as any unknown path).
4. Non-GET: `Origin` equals the `APP_URL` origin, `Sec-Fetch-Site` (if present) `same-origin`, `X-CSRF-Token` valid ⇒ 403 `CSRF_REJECTED`.
5. Session (state, idle, absolute, disabled user, revoked role) ⇒ 401 `SESSION_REQUIRED`.
6. Rate limit ⇒ 429 `TOO_MANY_REQUESTS` (+ `Retry-After`).
7. `params` parsed (failure ⇒ 404 on resource routes).
8. Authorisation through core ⇒ 403 `FORBIDDEN` or 404 `NOT_FOUND` (resource the caller may not know about).
9. Recent re-authentication ⇒ 403 `REAUTH_REQUIRED`.
10. `body` parsed ⇒ 422 `INVALID_INPUT` with `fields: { name: messageKey }`.
11. Handler. Unexpected error ⇒ 500 `INTERNAL` + correlation id.

Envelope `{ ok: true, data }` | `{ ok: false, error: { code, messageKey, fields?, retryAfterSeconds? } }`.

Cookies (always `__Host-`, Secure, Path=/; Chromium and Playwright accept them on http://localhost):

| Cookie | Content | Flags |
| --- | --- | --- |
| `__Host-mr-access` | `v1.<exp>.<mac>`, 12 h | HttpOnly, SameSite=Lax |
| `__Host-mr-session` | opaque token, browser-session cookie | HttpOnly, SameSite=Lax |
| `__Host-mr-csrf` | server-issued id + MAC | HttpOnly, SameSite=Lax |
| `__Host-mr-device` | per-account device token + MAC, 180 days | HttpOnly, SameSite=Strict |
| `__Host-mr-locale` | `ar` \| `fr` \| `zgh`, mapped through a fixed table on read (anything else ⇒ `ar`; message files imported statically) | SameSite=Lax |
| `__Host-mr-reading` | reading-ease preferences (`size=0..2`, `contrast=0..1`), validated on read | SameSite=Lax |

Headers on every response (static ones in `next.config.ts` `headers()` so they also cover 404 and assets; CSP per request in `proxy.ts`):

- `Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-<n>' 'strict-dynamic'; style-src 'self' 'nonce-<n>'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests` (no `unsafe-inline`, no `unsafe-hashes`; `unsafe-eval` only under `next dev`).
- `Strict-Transport-Security: max-age=63072000; includeSubDomains`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `X-Robots-Tag: noindex, nofollow`, `poweredByHeader: false`.
- `Cache-Control: no-store` on every `/api` answer and every dynamic page; `Clear-Site-Data: "cookies", "storage"` on logout.
- A test asserts each header on a page, an API answer, a 404 and `/healthz`.

CSP wiring (verified): the root layout reads the nonce with `await headers()` (`x-nonce`), which makes every route dynamic, `/_not-found` included; our own `not-found.tsx`, `error.tsx`, `global-error.tsx` without inline style; a client `NonceProvider` calls `setNonce(nonce)` from `get-nonce` before any Radix overlay mounts. A build check fails if the build output lists any prerendered (`○`) app route. The e2e CSP test runs against `next build && next start`, opens the account menu and a confirmation dialog, and visits an unknown URL. The nonce-based policy is a recorded decision (App Router needs nonce-tagged inline bootstrap scripts; our code adds none).

`src/proxy.ts`: default-deny matcher with an explicit allow-list for un-gated paths (`/_next/static/*`, `/healthz`, `/robots.txt`, `/access`, `/api/v1/access`, bundled fonts/icons); sets the CSP and nonce, issues `mr-csrf` when absent, redirects un-gated page requests to `/access?next=<safe path>`. It is a convenience, never the guard: every route re-checks.

## 8. Database

Documented first in `docs/data-model.md` (Arabic), then one dated migration created with `prisma migrate dev --create-only` with raw SQL appended, applied everywhere with `prisma migrate deploy`.

Tables: `Court` (degree `FIRST_INSTANCE` | `APPEAL`), `Organization`, `User` (+ `disabledAt`, `isDemo`, `lastLoginAt`), `RoleAssignment` (+ `verificationStatus`, `verificationSource`, `revokedAt`), `Session` (+ `origin`, `previousLoginAt`, `reauthAt`, `pendingExpiresAt`), `SecondFactorChallenge` (`codeMac`, `expiresAt`, `consumedAt`, `voidedAt`), `ActivationToken` (`tokenHash`, `expiresAt`, `usedAt`, `voidedAt`), `AuthAttempt` (`identifierHash`, `kind`, `ok`, `deviceBucket`, `clientIdHash`, `at`), `Lockout` (`identifierHash`, `cause`, `until`), `RateLimitHit`, `Event`, `OutboundMessage` (+ `visibleToSessionId`, `expiresAt`), `Notification` (`kind` `LEGAL_NOTIFICATION` | `INFORMATION` | `REMINDER`), `PlatformClock`, `SecretSetting`, `Job`, `SystemState` (`databaseMode`, `chainHeadSeq`, `chainHeadHash`, `chainStatus`, `lastVerifiedAt`), `InstitutionalIdentity`, `CaseFile` (minimal precursor), `Hearing`.

## 13. Definition of done for Phase 0

1. `npm run check` (lint, typecheck, unit, architecture), `npm run test:int`, `npm run build`, `npm run test:e2e` pass locally; `npm audit --audit-level=high` clean.
2. Logging in with each role (code read from the outbox) shows its dashboard with the three boxes (e2e, desktop and phone).
3. Every login and every refusal is in the event log (page and API refusals, throttle summaries); the log refuses UPDATE/DELETE/TRUNCATE/DISABLE TRIGGER/DROP as the runtime role; `npm run events:verify` passes and fails after deliberate tampering through the owner connection.
4. Lock after consecutive wrong passwords and after wrong codes, including across resends and new logins; a locked owner keeps a device-cookie path; attempts during a lock do not extend it.
5. Refusal matrix over both registries (endpoints and pages): without access cookie, without session, with a pending session, and with each of the 26 roles; the set of entries usable without a session equals an explicit allow-list; every non-GET endpoint appends at least one event on success.
6. `APP_MODE=production` refuses to boot (boot-check CLI in CI and integration tests), including with demo data, demo routes built, `DEMO_TOOLS=true`, a superuser runtime role.
7. No CSP violation on any page (built server, overlays opened, unknown URL), headers asserted, axe-core clean.
8. Local Docker image builds and answers `/healthz`.
9. Deployed from `main` after CI is green, `/healthz` answers 200 at `APP_URL`, and `npm run test:e2e` with `E2E_BASE_URL` passes against the published URL — **blocked until the owner provides the Railway project and authorises pushing to `main`** (reported, not faked).
10. End-of-phase documents: `docs/security/phase-0-review.md` written by agents that did not write the code, `docs/security/findings.md`, linguistic review, README, the phase report.
